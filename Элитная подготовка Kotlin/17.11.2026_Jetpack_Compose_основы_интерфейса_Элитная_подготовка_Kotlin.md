## Что такое Jetpack Compose

**Jetpack Compose** — декларативный подход к построению Android-интерфейса на Kotlin. Вместо отдельного XML с последующим поиском `View` разработчик описывает интерфейс composable-функциями: какие элементы показать и как они зависят от состояния. При изменении наблюдаемого состояния Compose может повторно выполнить затронутые функции и обновить интерфейс — это называется **рекомпозицией**.

В проекте точка входа в интерфейс находится в `MainActivity.onCreate`:

```kotlin
setContent {
    LessonJetpackStartTheme {
        Lists()
    }
}
```

`setContent` размещает Compose-содержимое в Activity, тема задаёт оформление, а `Lists()` описывает конкретное содержимое. Это другой способ построения экрана по сравнению с `setContentView(R.layout...)` из предыдущего проекта. [Основы Compose](https://developer.android.com/develop/ui/compose/mental-model).

## Подключение и структура проекта

В [Gradle-файле модуля](https://github.com/docfr10/Lesson-JetpackStart/blob/1a352b81c0a99cd2b05d1ba379f704ab9d7129be/app/build.gradle.kts) включены плагин Kotlin Compose и `buildFeatures { compose = true }`. Среди зависимостей — `activity-compose`, Compose UI, Material 3 и инструменты предпросмотра. Compose BOM задаёт согласованные версии Compose-библиотек, перечисленных без собственных номеров; сама платформа не добавляет их автоматически.

В снимке заданы `compileSdk` и `targetSdk` 37, `minSdk` 24, Compose BOM `2026.02.01`. Это настройки учебного проекта, а не обязательные версии для любого приложения. `compileSdk` определяет API для компиляции, `minSdk` — минимальный уровень устройства, а `targetSdk` — уровень, на поведение которого ориентировано приложение.

## Composable-функции и предпросмотр

`@Composable` помечает функцию, которая участвует в описании интерфейса Compose. Её можно вызывать из другого composable-контекста, например из `setContent` или другой composable-функции. `Text` выводит строку:

```kotlin
@Composable
@Preview(showBackground = true, showSystemUi = true)
fun UserInterface() {
    Text(
        text = "Hello, World!",
        modifier = Modifier.padding(horizontal = 100.dp, vertical = 150.dp)
            .size(200.dp),
        fontSize = 30.sp
    )
}
```

`@Preview` позволяет Android Studio построить предварительный просмотр без запуска приложения на устройстве. Аннотация сама по себе не добавляет функцию в экран приложения. `showBackground` включает фон предпросмотра, `showSystemUi` — имитацию системного окружения. [Предпросмотр Compose](https://developer.android.com/develop/ui/compose/tooling/previews).

## Modifier и размеры

`Modifier` описывает ограничения, оформление и поведение элемента. В проекте используются:

| Вызов | Назначение |
|---|---|
| `padding(...)` | отступ вокруг содержимого |
| `size(100.dp)` | запрашиваемый размер с учётом ограничений родителя |
| `fillMaxWidth()`, `fillMaxHeight()`, `fillMaxSize()` | заполнение доступного размера по соответствующим осям |
| `background(Color.Red)` | фон элемента |
| `border(2.dp, Color.Green)` | обводка |
| `clip(CircleShape)` | обрезка содержимого по форме |

Порядок модификаторов имеет значение: например, рамка до и после `padding` окажется на разных границах. `dp` используют для размеров интерфейса с учётом плотности экрана, `sp` — для размера текста с учётом настроек масштаба шрифта. Нельзя считать `dp` физическими пикселями. [Модификаторы Compose](https://developer.android.com/develop/ui/compose/modifiers).

## Контейнеры Column, Row и Box

В `Containers()` показаны три базовых способа расположения элементов:

| Контейнер | Расположение | Пример настройки |
|---|---|---|
| `Column` | по вертикальной оси | `verticalArrangement = Arrangement.spacedBy(20.dp)` задаёт промежутки |
| `Row` | по горизонтальной оси | `horizontalArrangement = Arrangement.SpaceBetween` распределяет свободное пространство между элементами |
| `Box` | в одной области, с возможным наложением | `contentAlignment = Alignment.BottomStart` задаёт общее выравнивание |

Например, вертикальный список из трёх надписей можно описать так:

```kotlin
Column(verticalArrangement = Arrangement.spacedBy(20.dp)) {
    Text("Text 1")
    Text("Text 2")
    Text("Text 3")
}
```

В исходной функции все три контейнера вызваны рядом без общего `Column`: это не означает автоматического размещения одного под другим. `Box` содержит три текста с одинаковым выравниванием, поэтому они могут накладываться. `Start` и `End` учитывают направление текста интерфейса, а не всегда обозначают физические лево и право. [Базовые макеты](https://developer.android.com/develop/ui/compose/layouts/basics).

## Состояние и рекомпозиция

`Elements()` демонстрирует счётчик:

```kotlin
val count = remember { mutableStateOf(0) }
Button(onClick = {
    Log.e("Button", "На кнопку нажали ${count.value} раз")
    count.value++
}) {
    Text("На меня нажали ${count.value}")
}
```

`mutableStateOf(0)` создаёт наблюдаемое состояние, а `remember` сохраняет созданный объект между рекомпозициями, пока этот вызов остаётся в композиции. Нажатие меняет `count.value`; функция, читающая состояние, может быть вызвана повторно и показать обновлённое число. В этом примере в журнал записывается значение **до** увеличения, а надпись после обновления показывает новое значение.

Второй синтаксис используется для строк полей ввода:

```kotlin
var textField1 by remember { mutableStateOf("") }
```

Делегирование `by` позволяет читать и присваивать значение без явного `.value`; для него в файле импортированы `getValue` и `setValue`. Состояние `remember` само по себе не гарантирует сохранение при пересоздании Activity или после удаления элемента из композиции. Для подходящих сохраняемых значений используют `rememberSaveable`, а для более сложного состояния — подходящий владелец состояния, например `ViewModel`. [Состояние в Compose](https://developer.android.com/develop/ui/compose/state).

## Текстовые поля и изображения

В проекте используются управляемые состоянием поля:

```kotlin
TextField(value = textField1, onValueChange = { textField1 = it })
OutlinedTextField(
    placeholder = { Text("Заголовок") },
    value = textField2,
    onValueChange = { textField2 = it }
)
```

`value` задаёт показываемый текст, а `onValueChange` получает новое значение при вводе; сохранение его в состоянии вызывает обновление поля. `placeholder` показывается, когда поле пусто, и не заменяет постоянную подпись `label`. `OutlinedTextField` — вариант с контуром; `TextField` в Material 3 обычно имеет заполненный фон. Комментарии в исходном коде о наличии обводки у этих двух полей перепутаны.

`Image` принимает изображение через `painterResource`: пример показывает векторный `R.drawable.ic_launcher_foreground` и растровый `R.mipmap.images`. `alpha = 1f` задаёт полную непрозрачность. `contentDescription` помогает пользователям средств доступности понять смысл содержательного изображения; для чисто декоративной картинки уместно `null`. [Изображения в Compose](https://developer.android.com/develop/ui/compose/graphics/images/loading).

## Списки LazyColumn

Активный экран приложения вызывает `Lists()`:

```kotlin
LazyColumn(modifier = Modifier.fillMaxSize().padding(25.dp)) {
    item { Text("Один элемент списка") }
    items(100) { index ->
        Text(index.toString())
        Image(
            painter = painterResource(id = R.mipmap.images),
            contentDescription = "Изображение растровое"
        )
    }
}
```

`LazyColumn` — вертикальный прокручиваемый список, который формирует содержимое по мере необходимости. `item` добавляет один элемент, `items(100)` создаёт 100 элементов с индексами от 0 до 99. Внутри каждого элемента этого примера находятся и текст, и изображение: это одна единица списка, а не две отдельные записи. Для списков изменяемых данных стабильные ключи помогают Compose сохранять соответствие состояния элементам при перестановках. [Списки Compose](https://developer.android.com/develop/ui/compose/lists).

## Тема приложения

[`LessonJetpackStartTheme`](https://github.com/docfr10/Lesson-JetpackStart/blob/1a352b81c0a99cd2b05d1ba379f704ab9d7129be/app/src/main/java/com/example/lesson_jetpackstart/ui/theme/Theme.kt) выбирает светлую или тёмную цветовую схему по настройке системы и передаёт её вместе с типографикой в `MaterialTheme`. На Android 12 и новее при включённом `dynamicColor` используется динамическая цветовая схема; иначе выбираются заданные в проекте светлые или тёмные цвета. Параметр `content: @Composable () -> Unit` позволяет обернуть в тему любое переданное Compose-содержимое.

## Что важно в учебном примере

- `enableEdgeToEdge()` позволяет содержимому располагаться у краёв окна, но фиксированный `padding(25.dp)` не является универсальной заменой обработки системных отступов: результат стоит проверить на устройствах с разными системными панелями.
- Большие фиксированные отступы и размеры в `UserInterface()` и `Containers()` могут занимать большую часть доступного экрана; размеры зависят от ограничений родителя. Разметку следует проверять на экранах разного размера.
- В `Elements()` текст кнопки, поля и состояние — демонстрационные: сведения из полей никуда не отправляются и после пересоздания Activity обычным `remember` не сохраняются.
- Показанные в коде строки захардкожены; для локализации приложения их обычно выносят в строковые ресурсы. Описание повторяющейся картинки в списке следует выбирать исходя из её реального смысла.

## Главное

1. `setContent` запускает описание Compose-интерфейса, а `@Composable` помечает составляющие его функции.
2. `Modifier` задаёт размеры, отступы и оформление; порядок операций влияет на результат.
3. `Column`, `Row` и `Box` организуют элементы по вертикали, горизонтали и в общей области.
4. Изменение читаемого Compose-состояния может вызвать рекомпозицию; `remember` сохраняет объект между рекомпозициями, но не обязательно после пересоздания Activity.
5. `TextField` получает значение и сообщает о вводе через `onValueChange`; `LazyColumn` отображает прокручиваемый список по мере необходимости.
