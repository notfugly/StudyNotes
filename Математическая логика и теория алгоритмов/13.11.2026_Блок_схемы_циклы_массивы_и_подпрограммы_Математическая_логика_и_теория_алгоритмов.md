# Блок-схемы и структуры алгоритмов

**13.11.2026 · Математическая логика и теория алгоритмов · Лекция**

## Виды схем

Схема с помощью условных обозначений показывает данные, процессы и связи между ними. В зависимости от того, что требуется представить, применяют разные виды схем.

| Вид схемы | Что отображает |
|---|---|
| **Схема данных** | Путь данных при решении задачи, этапы обработки и используемые носители данных. |
| **Схема программы** | Последовательность операций программы и поток управления между ними. |
| **Схема работы системы** | Управление операциями и потоки данных между процессами и носителями. |
| **Схема взаимодействия программ** | Путь активации программ и взаимодействие программ с соответствующими данными. |
| **Схема ресурсов системы** | Конфигурацию блоков данных и обрабатывающих блоков, необходимых для решения задачи; связи устройств и процессоров. |

В схеме данные и операции обозначают соответствующими символами, а линии показывают связи и направление потока.

## Символы блок-схем

| Символ | Форма и назначение |
|---|---|
| Данные | Параллелограмм; данные без указания конкретного носителя, в том числе ввод или вывод. |
| Запоминаемые данные | Показывает хранимые данные, пригодные для обработки; конкретный носитель не определён. |
| Оперативная память | Данные, хранящиеся в оперативном запоминающем устройстве. |
| Запоминающее устройство с прямым доступом | Данные на носителе с прямым доступом, например на диске. |
| Документ | Прямоугольник с волнистым нижним краем; данные в удобочитаемой форме, например распечатка. |
| Ручной ввод | Данные, вводимые человеком с устройства ввода. |
| Дисплей | Данные, отображаемые на экране или другом устройстве отображения. |
| Процесс | Прямоугольник; операция или последовательность операций, изменяющих данные. |
| Предопределённый процесс | Прямоугольник с дополнительными вертикальными линиями по краям; действия, определённые отдельно, например в подпрограмме. |
| Ручная операция | Трапеция; процесс, выполняемый человеком. |
| Подготовка | Шестиугольник; подготовительные действия, в том числе установка начальных значений. |
| Решение | Ромб; проверка условия и выбор одного из выходов. |
| Параллельные действия | Пара линий, обозначающая синхронизацию параллельных операций. |
| Граница цикла | Два согласованных символа начала и конца цикла с одинаковым идентификатором. |
| Линия | Показывает поток данных или управления. |
| Передача управления | Обозначает непосредственную передачу управления другому процессу; тип передачи указывается внутри символа. |
| Пунктирная линия | Показывает связь комментария с символом или объединяет выделенную группу символов. |
| Соединитель | Показывает переход к другой части схемы и позволяет разрывать длинные линии. |
| Терминатор | Скруглённый прямоугольник; начало или конец схемы. |
| Комментарий | Пояснение, связанное с соответствующим символом пунктирной линией. |
| Пропуск | Обозначает пропущенный символ или группу символов. |

При разветвлении рядом с выходами решения указывают соответствующие условия или ответы «да» и «нет». Символы начала и конца цикла образуют пару: между ними размещают повторяемые действия.

## Правила построения схем

- Символы располагают равномерно, стремясь к коротким соединениям и небольшому числу длинных линий. В одной схеме удобно использовать блоки одинаковых размеров; при необходимости их нумеруют.
- В символе помещают минимальный текст, необходимый для понимания действия. Текст читают слева направо и сверху вниз.
- Обычное направление потока — слева направо и сверху вниз; изменение направления обозначают стрелкой.
- Пересечения линий следует по возможности избегать. Само пересечение не означает логической связи; поворот на пересечении не допускается. При слиянии входящих линий точку объединения делают различимой.
- Длинную линию или переход на другую страницу можно обозначить парой соединителей с одинаковой меткой. При нескольких выходах из символа используют отдельные линии или одну разветвляющуюся линию.

Для **проверки на тестовом примере** блоки схемы удобно пронумеровать и последовательно записывать номер выполняемого блока и значения переменных после действия. Если блок выполняется в цикле несколько раз, к его номеру добавляют номер итерации: например, $7(1)$, $7(2)$. Такая трассировка показывает, как меняются данные и какая ветвь выбирается.

## Базовые структуры алгоритмов

Простая команда обозначает элементарное действие. Составные команды строятся из простых команд и проверок условия. Базовые структуры имеют один вход и один выход и могут вкладываться друг в друга.

| Структура | Выполнение |
|---|---|
| Следование | Действия выполняются последовательно, одно за другим. |
| Полное ветвление | При истинном условии выполняется одно действие, при ложном — другое; затем ветви соединяются. |
| Неполное ветвление | При истинном условии выполняется действие, при ложном управление проходит дальше. |
| Цикл | Тело повторяется; число повторений определяется параметром или условием. |

Например, полное ветвление можно записать так:

```text
если условие:
    действие 1
иначе:
    действие 2
```

Присваивание изменяет значение переменной: запись $x\leftarrow E$ означает вычислить выражение $E$ и сохранить результат в $x$.

## Примеры линейных и разветвлённых алгоритмов

### Вычисление выражения

Пусть требуется найти

$$y=\frac{b^2-ac}{a+c},\qquad a+c\ne0.$$

Последовательность действий: ввести $a,b,c$; вычислить $p=b^2-ac$ и $q=a+c$; затем найти $y=p/q$ и вывести его. При $a+c=0$ деление не определено.

### Функция с тремя ветвями

При $a<b$ рассмотрим функцию

$$z=\begin{cases}
0{,}5x^2+1,&x\le a,\\
\cos x,&a<x<b,\\
\tan^2x,&x\ge b.
\end{cases}$$

После ввода $x,a,b$ выбирают одну из трёх ветвей, вычисляют $z$ и выводят результат. В схеме выбора у каждого выхода записывают его условие, а затем ветви соединяются перед выводом. В последней ветви требуется $\cos x\ne0$, поскольку иначе тангенс не определён. Условие $a<b$ обеспечивает непересечение указанных диапазонов.

### Принадлежность точки кругу

Для круга радиуса $R>0$ с центром в начале координат точка $(X,Y)$ принадлежит кругу вместе с границей тогда и только тогда, когда

$$X^2+Y^2\le R^2.$$

Алгоритм вводит $X,Y,R$, проверяет неравенство и выводит «принадлежит» или «не принадлежит». Например, при $R=5$ точка $(3,4)$ лежит на границе, поскольку $3^2+4^2=25$.

Если центр круга находится в точке $(x_0,y_0)$, вместо координат точки используют её смещение относительно центра. Условие принадлежности принимает вид

$$(X-x_0)^2+(Y-y_0)^2\le R^2.$$

## Циклические алгоритмы

**Тело цикла** — повторяемые действия; одно выполнение тела называется **итерацией**. Для управления повторениями задают начальные значения, проверяют условие и изменяют управляющие переменные. При проектировании необходимо обеспечить достижение условия выхода: бесконечный цикл не выдаёт результат за конечное число шагов.

| Вид | Проверка и число выполнений |
|---|---|
| С предусловием | Условие проверяется перед телом; тело может не выполниться ни разу. |
| С постусловием | Условие проверяется после тела; тело выполняется хотя бы один раз. |
| С параметром | Параметр последовательно принимает значения заданного диапазона; на каждом значении выполняется тело. |

Для параметра, который начинается с $a$, увеличивается на $h>0$ и принимает значения, не превышающие $b$, число итераций при $a\le b$ равно

$$N=\left\lfloor\frac{b-a}{h}\right\rfloor+1.$$

Если $a>b$, таких значений нет. Если значения обрабатываемой величины не образуют последовательность с удобным правилом изменения, их можно хранить в массиве и в цикле изменять индекс элемента.

Для цикла с предусловием условие продолжения проверяется до каждого прохода:

```text
начальная установка
пока условие продолжения:
    тело цикла
    изменение параметра
```

В цикле с постусловием действие выполняется перед проверкой. Нужно различать **условие продолжения** и **условие выхода**: они противоположны друг другу. Цикл со счётчиком во многих языках задаётся конструкцией `for`: обычно условие проверяется перед телом, так что такой цикл можно представить через цикл с предусловием. Конкретный порядок изменения счётчика зависит от языка.

Если параметр последовательно принимает значения $0,2,4,\ldots,20$, то число значений равно $(20-0)/2+1=11$. Например, для каждого значения можно вычислить и вывести $y=\sin x$.

Для суммирования десяти введённых чисел задают $S=0$, $i=1$; затем вводят очередное число, добавляют его к $S$, увеличивают $i$ на единицу и повторяют до обработки десяти чисел. После этого выводят сумму.

## Накопление суммы и произведения

**Накопление** последовательно обновляет результат при обработке каждого элемента:

| Задача | Начальное значение | Обновление |
|---|---|---|
| Сумма | $S=0$ | $S\leftarrow S+a_i$ |
| Произведение | $P=1$ | $P\leftarrow P\cdot a_i$ |
| Подсчёт | $C=0$ | $C\leftarrow C+1$ для каждого учитываемого объекта |

Например, для конечной суммы и произведения

$$S=\sum_{i=2}^{100}\frac{i+1}{i+2},\qquad P=\prod_{i=1}^{25}\frac{i^2}{i^2+2i+3}$$

сначала задают соответственно $S=0$ и $P=1$, а затем перебирают все целые индексы с шагом 1. Для суммы выполняется 99 итераций; для произведения — 25.

Накопление сумм применяется и в численном интегрировании: отрезок делят на части, а интеграл приближают суммой вкладов от отдельных частей. Например, метод прямоугольников использует произведения значения функции на ширину соответствующего промежутка. При подходящих условиях уменьшение ширины разбиения улучшает приближение.

## Массивы и их обработка

**Массив** — совокупность элементов с общим именем, различаемых индексами. Размер массива — число элементов; размерность — число индексов, необходимых для обращения к элементу. Для прямоугольного двумерного массива из $m$ строк и $n$ столбцов общее число элементов равно $mn$.

- Одномерный массив: $A(1),A(2),\ldots,A(n)$.
- Двумерный массив: таблица или матрица $a_{ij}$, где первый индекс задаёт строку, второй — столбец.
- Символы текста также можно рассматривать как последовательность, элементы которой определяются номером позиции.

### Обратный порядок

Пусть массив $A$ из 20 элементов упорядочен по убыванию. Чтобы получить массив $B$ в обратном порядке, для $i=1,\ldots,20$ выполняют

$$B(i)=A(21-i).$$

Первый элемент $B$ получает значение $A(20)$, второй — $A(19)$, последний — $A(1)$. В результате массив $B$ упорядочен по возрастанию, если исходный массив упорядочен по убыванию.

### Поиск символа в строке

Для поиска заданного символа последовательно просматривают символы строки и сравнивают каждый с искомым. При совпадении можно вывести индекс найденного символа; если пройдена вся строка и совпадений нет, выводят сообщение об отсутствии. Чтобы найти все вхождения, просмотр продолжают после совпадения до конца строки.

### Сортировка соседними обменами

**Пузырьковая сортировка** последовательно сравнивает соседние элементы и меняет их местами, если они идут в неправильном порядке. Для сортировки по возрастанию обмен выполняют при $A(j)>A(j+1)$. После первого прохода максимальный элемент оказывается в конце, после второго — на предпоследнем месте; поэтому проверяемую часть можно сокращать.

Для массива $A(1),\ldots,A(n)$ алгоритм с фиксированным числом проходов записывается так:

```text
для i от 1 до n − 1:
    для j от 1 до n − i:
        если A(j) > A(j + 1):
            обменять A(j) и A(j + 1)
```

За проходы выполняется $(n-1)+(n-2)+\cdots+1=n(n-1)/2$ сравнений; при обратном порядке для различных элементов столько же обменов. При такой реализации сложность по числу сравнений — $O(n^2)$, а для обмена нужна лишь постоянная дополнительная память. Если за полный проход не было ни одного обмена, массив уже упорядочен и работу можно завершить раньше.

Другой способ соседних обменов — последовательно поддерживать упорядоченный начальный фрагмент и передвигать каждый следующий элемент влево до его места. Это сортировка вставками с обменами; в худшем случае она также требует квадратичного числа операций.

## Вложенные и итерационные циклы

**Вложенный цикл** расположен внутри тела другого цикла. Для каждого прохода внешнего цикла внутренний проходит свой диапазон; завершение внутреннего прохода предшествует следующей итерации внешнего. Действия, не зависящие от параметра внутреннего цикла, можно вынести из его тела, если это сохраняет порядок и смысл вычислений. Для счётчиков вложенных циклов следует использовать разные имена и учитывать их область видимости, чтобы внутренний цикл случайно не изменил параметр внешнего.

Например, нужно вычислить

$$A(x)=\prod_{k=1}^{n}\sqrt{x^2+k^2}$$

для $x=0,0{,}5,\ldots,5$ и заданного натурального $n$. Внешний цикл перебирает значения $x$; для каждого из них следует заново положить $A=1$, во внутреннем цикле умножить $A$ на $\sqrt{x^2+k^2}$ при $k=1,\ldots,n$, а затем вывести $A$.

```text
для x от 0 до 5 с шагом 0,5:
    A ← 1
    для k от 1 до n:
        A ← A · √(x² + k²)
    вывести x, A
```

При упорядочивании массива последовательными проходами возможна схема с $n-1$ проходами и $n(n-1)/2$ сравнениями, если на каждом следующем проходе сокращать проверяемую часть на один элемент.

В **итерационном алгоритме** число повторений заранее может быть неизвестно. Приближение последовательно уточняют, а после каждого шага проверяют условие остановки. Нужно отдельно обосновать, что условие выхода достижимо и выбранный критерий обеспечивает нужную точность.

Например, члены знакопеременного ряда для синуса можно получать без повторного вычисления степеней и факториалов:

$$u_n=(-1)^{n-1}\frac{x^{2n-1}}{(2n-1)!},\qquad u_1=x,\qquad u_{n+1}=-\frac{x^2}{2n(2n+1)}u_n.$$

Частичную сумму обновляют по формуле $S\leftarrow S+u_n$, затем находят следующий член по рекуррентной формуле. При подходящем критерии малости очередного члена вычисление останавливают; для оценки остатка знакопеременного ряда необходимо учитывать условия убывания модулей его членов.

**Критерий остановки нужно обосновывать.** Например, условие $|u_n-u_{n+1}|\le d$ само по себе не гарантирует ни сходимости ряда, ни погрешности его суммы меньше $d$. Для гармонического ряда $u_n=1/n$ разность соседних членов стремится к нулю, хотя ряд расходится. В случае знакочередующегося ряда оценка остатка первым отброшенным членом применима, когда модули членов убывают к нулю.

## Подпрограммы

Повторяющуюся логически законченную группу действий можно выделить в **подпрограмму** и вызывать по имени из разных мест программы. Это уменьшает дублирование и облегчает разработку и проверку.

**Процедура** выполняет действия при вызове; **функция** возвращает вызывающему коду значение, которое можно использовать в выражении. Конкретные правила описания, вызова и возвращаемые типы зависят от языка программирования. Бывают встроенные подпрограммы языка и подпрограммы, написанные пользователем. Имена, объявленные внутри подпрограммы, обычно локальны: непосредственно использовать их за пределами соответствующей области видимости нельзя; точные правила области видимости определяет язык.

При проектировании подпрограммы необходимо:

1. Определить её назначение и решить, требуется процедура или функция.
2. Выбрать входные данные и результаты, передаваемые через параметры или возвращаемое значение.
3. Определить локальные данные и по возможности ограничить использование глобальных.
4. Выбрать допустимый в языке способ передачи параметров, учитывая возможность изменения данных и стоимость передачи.

## Главное

- Различные виды схем показывают движение данных, управление, взаимодействие программ или устройство системы.
- Блок-схема использует условные символы процессов, данных, решений и линий потока.
- Следование, ветвление и цикл образуют основные структуры алгоритмов.
- Цикл с предусловием может не выполниться; цикл с постусловием выполняется хотя бы один раз.
- Для конечного результата необходимо обеспечить достижение условия выхода из цикла.
- Сумму накапливают с нуля, произведение — с единицы; индексы позволяют последовательно обрабатывать элементы массивов.
- Во вложенных циклах внутренний цикл выполняется для каждого прохода внешнего.
- Подпрограмма выделяет повторяемые действия; функция возвращает значение, а процедура выполняет действия.
