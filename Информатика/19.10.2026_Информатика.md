## Темы контрольной работы и требования к алгоритмам

Пять групп задач посвящены количеству информации, кодированию текста, помехоустойчивым кодам, системам счисления и машинному представлению чисел. Задания оцениваются соответственно в 1, 2, 3, 4 и 5 баллов.

Решение выполняется на Python. Если требуется собственный алгоритм, встроенная функция не должна его подменять. Например, поразрядное сложение нужно реализовать переносами, а перевод в десятичную систему использовать только для проверки.

## Формула Хартли и энтропия Шеннона

Для $N$ равновероятных сообщений:

$$I=\log_2N\quad\text{бит}.$$

Для вероятностей $p_i\ge0$, $\sum p_i=1$:

$$H=-\sum_i p_i\log_2p_i,$$

причём вклад $p_i=0$ принимают равным нулю по пределу. Это среднее количество информации на сообщение источника.

| Вариант | Данные | Результат |
|---|---|---|
| 1 | $N=128$ | 7 бит |
| 2 | $N=256$ | 8 бит |
| 3 | четыре равновероятных сообщения | 2 бита |
| 4 | $N=32$ | 5 бит |
| 5 | $p=(0{,}5;0{,}25;0{,}125;0{,}125)$ | $H=1{,}75$ бита |

В последнем случае $H=0{,}5\cdot1+0{,}25\cdot2+2\cdot0{,}125\cdot3=1{,}75$.

```python
from math import log2

def entropy(probabilities):
    if any(p < 0 for p in probabilities):
        raise ValueError("Вероятности должны быть неотрицательными")
    if abs(sum(probabilities) - 1.0) > 1e-12:
        raise ValueError("Сумма вероятностей должна быть равна 1")
    return -sum(p * log2(p) for p in probabilities if p > 0)
```

## Фиксированные и переменные коды

При фиксированном коде каждой букве соответствует одинаковое число бит. Для трёх букв достаточно двух бит, поскольку $2^1<3\le2^2$. При переменном коде длины слов могут различаться.

Код $A\mapsto0$, $B\mapsto10$, $C\mapsto11$ **префиксный**: ни одно слово не является началом другого. Поэтому последовательность декодируется слева направо без разделителей.

| Сообщение | Код | Последовательность | Длина |
|---|---|---|---|
| ABACABA | $A=0,B=10,C=11$ | 0100110100 | 10 бит |
| BACABCA | $A=00,B=01,C=10$ | 01001000011000 | 14 бит |
| ABBCABA | тот же фиксированный | 00010110000100 | 14 бит |
| AABACABA | переменный | 00100110100 | 11 бит |
| CADBAC | $A=00,B=01,C=10,D=11$ | 100011010010 | 12 бит |

Для AABACABA средняя длина $11/8=1{,}375$ бита на символ; фиксированный двухбитный код занял бы 16 бит. Для ABBCABA кодировка UTF-8 использует 7 байт, то есть 56 бит, поскольку все буквы латинские ASCII; разница с двухбитным кодом — 42 бита.

```python
def decode_prefix(bits, table):
    inverse = {code: char for char, code in table.items()}
    result, current = [], ""
    for bit in bits:
        if bit not in "01":
            raise ValueError("Ожидалась двоичная строка")
        current += bit
        if current in inverse:
            result.append(inverse[current])
            current = ""
        elif not any(code.startswith(current) for code in inverse):
            raise ValueError("Неизвестное кодовое слово")
    if current:
        raise ValueError("Незавершённое кодовое слово")
    return "".join(result)
```

Алгоритм предполагает заранее проверенную префиксную таблицу. После кодирования и декодирования обязательно сравнивают восстановленную строку с исходной.

## Троирование и бит чётности

**Троирование:** $0\mapsto000$, $1\mapsto111$. Декодирование каждой тройки — по большинству. Оно исправляет одну ошибку в каждой тройке, но две ошибки в одной тройке меняют результат.

Для $10110$ код равен $111\,000\,111\,111\,000$. Изменение второго бита второй тройки даёт $111\,010\,111\,111\,000$; большинство восстанавливает $10110$.

Для $11001$ получаем $111\,111\,000\,000\,111$. Ошибки в позициях 2, 8, 14 попадают в разные тройки, поэтому все исправляются правилом большинства. Нумерация позиций в условии начинается с 1, индекс в Python — с 0.

**Бит чётности** выбирают так, чтобы число единиц во всём слове стало чётным. Для $1101011$ число единиц равно 5, поэтому добавляют $1$ и получают $11010111$. Одна ошибка меняет чётность и обнаруживается. Две ошибки в позициях 2 и 5 сохраняют чётность, поэтому такая проверка их не обнаруживает.

Чётность обнаруживает нечётное число инверсий, но не указывает место ошибки.

## Расстояние Хэмминга и код Хэмминга

**Расстояние Хэмминга** — число различающихся позиций слов одной длины. Для $10110110$ и $10011101$ это позиции $3,5,7,8$, расстояние $4$. Инверсия позиций 3 и 6 первого слова создаёт слово на расстоянии $2$ от него.

В коде **Хэмминга (7,4)** контрольные биты находятся на позициях 1, 2, 4, информационные — на 3, 5, 6, 7. При чётных проверках:

$$p_1=d_1\oplus d_2\oplus d_4,\quad p_2=d_1\oplus d_3\oplus d_4,\quad p_4=d_2\oplus d_3\oplus d_4.$$

Для $d_1d_2d_3d_4=1011$ имеем $p_1=0$, $p_2=1$, $p_4=0$, кодовое слово **0110011**. Инверсия пятого бита даёт **0110111**.

Проверки принятого слова $c$:

$$s_1=c_1\oplus c_3\oplus c_5\oplus c_7,$$
$$s_2=c_2\oplus c_3\oplus c_6\oplus c_7,$$
$$s_4=c_4\oplus c_5\oplus c_6\oplus c_7.$$

Номер ошибки $s=s_1+2s_2+4s_4=5$. Инвертируем бит 5 и извлекаем позиции 3, 5, 6, 7 — получаем 1011. **Коррекция предполагает не более одной ошибки в слове**; обычный код (7,4) не обеспечивает надёжное исправление двух ошибок.

## Позиционные системы счисления

Для основания $b$ цифры удовлетворяют $0\le a_i<b$:

$$N=\sum_i a_ib^i.$$

Перевод в десятичную систему удобно выполнять схемой Горнера: последовательно $value\leftarrow value\cdot b+digit$. Обратный перевод целого неотрицательного числа — последовательное деление на основание; остатки читают в обратном порядке.

Для $347_{10}$:

```text
347 = 69·5 + 2
 69 = 13·5 + 4
 13 =  2·5 + 3
  2 =  0·5 + 2
```

Значит, $347_{10}=2342_5$; проверка $2\cdot125+3\cdot25+4\cdot5+2=347$.

Для $2B7_{16}$: $2\cdot256+11\cdot16+7=695_{10}=10240_5$. Перед переводом нужно проверить, что каждая цифра допустима в исходном основании.

Если основания — степени двойки, используют группировку справа налево: для восьмеричной системы по 3 бита, для шестнадцатеричной по 4. При необходимости слева дописывают нули:

$$110\ 101\ 110\ 101_2=6565_8,$$
$$1101\ 0111\ 0101_2=D75_{16}.$$

## Поразрядная арифметика

При сложении в основании $b$ для текущего разряда $s=a_i+b_i+carry$; новая цифра $s\bmod b$, перенос $\lfloor s/b\rfloor$.

Для $567_8+245_8$:

- $7+5=12_{10}=14_8$: записываем 4, перенос 1.
- $6+4+1=11_{10}=13_8$: записываем 3, перенос 1.
- $5+2+1=8_{10}=10_8$: записываем 0, перенос 1.
- Последний перенос создаёт старшую цифру 1.

Ответ **$1034_8$**, три переноса.

При вычитании $d=a_i-b_i-borrow$. Если $d<0$, прибавляют основание и занимают единицу следующего разряда. Для $754_8-367_8$ получаем **$365_8$**, два заимствования. Десятичная проверка: $492-247=245$.

## Дополнительный код и переполнение

Диапазон знакового $n$-битного дополнительного кода:

$$-2^{n-1}\le x\le2^{n-1}-1.$$

Отрицательное $x$ кодируется как $2^n+x$. Результат сложения хранится по модулю $2^n$. Если старший бит равен 1, десятичное значение кода $u$ равно $u-2^n$.

**Знаковое переполнение при сложении:** операнды одинакового знака дали результат противоположного знака. Перенос за границу слова сам по себе не является этим критерием.

Для 8 бит:

| Операция | Сохранённый результат | Переполнение |
|---|---|---|
| $100+50$ | 10010110, то есть $-106$ | да |
| $100-50$ | 00110010, то есть $50$ | нет |
| $90+60$ | $-106$ | да |
| $-100-40$ | $116$ | да |
| $70-30$ | $40$ | нет |

Вычитание реализуют сложением с дополнительным кодом отрицательного второго операнда. В Python целые числа не переполняются автоматически, поэтому ширину моделируют маской $(1\ll n)-1$.

## Фиксированная точка

При $f$ дробных битах масштаб равен $2^f$, шаг $2^{-f}$:

$$q=\operatorname{round}(x2^f),\qquad\hat x=q/2^f,\qquad\Delta=|\hat x-x|.$$

После округления проверяют, что $q$ попадает в знаковый диапазон машинного слова.

При 8 битах и $f=3$: $5{,}375\cdot8=43$, код 00101011, восстановление точное. Число $5{,}3$ округляется к $42/8=5{,}25$, погрешность $0{,}05$; $5{,}7$ — к $46/8=5{,}75$, погрешность также $0{,}05$.

При четырёх дробных битах:

| $x$ | $q$ | $\hat x$ | Абсолютная погрешность |
|---|---|---|---|
| 0,1 | 2 | 0,125 | 0,025 |
| 0,25 | 4 | 0,25 | 0 |
| 0,3 | 5 | 0,3125 | 0,0125 |
| 0,625 | 10 | 0,625 | 0 |

## Плавающая точка и порядок операций

Двоичный формат точно представляет не все десятичные дроби. Числа 0,25 и 0,625 имеют конечную двоичную запись, а 0,1 и 0,3 — бесконечную, поэтому хранятся приближённо.

Округление может нарушить ассоциативность сложения. Для $x=10^{16}$ математически оба выражения равны единице, но при вычислении с `float`:

```python
x = 1e16
print((x + (-x)) + 1)  # 1.0
print(x + ((-x) + 1))  # 0.0
```

Во втором выражении единица теряется при сложении с большим по модулю числом. Абсолютные погрешности — 0 и 1. Для $10^{12}$ и $10^{14}$ оба результата равны 1; для $10^{18}$ второй снова равен 0 в рассматриваемом формате `float`.

При сравнении с исходной десятичной дробью её точное значение удобно хранить через `Decimal` от строки, иначе эталон уже может содержать двоичную погрешность.

## Главное

- Хартли применяется к равновероятным сообщениям; Шеннон — к заданному распределению.
- Префиксность позволяет однозначно декодировать переменные кодовые слова.
- Троирование исправляет одну ошибку на тройку, чётность обнаруживает нечётное число инверсий.
- Синдром Хэмминга указывает позицию одиночной ошибки.
- Поразрядная арифметика должна учитывать основание и переносы.
- Дополнительный код требует фиксированной ширины и отдельной проверки знакового переполнения.
- Фиксированная точка имеет постоянный шаг; плавающая точка может терять точность при изменении порядка операций.
