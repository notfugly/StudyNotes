# Семантика перемещения: rvalue-ссылки, std::move и std::forward

**Дата занятия:** 23.10.2026.  
**Предмет:** C++.

Базовые средства перемещения появились в C++11. Примеры ниже ориентированы на **C++17**; различия с другими версиями языка указаны отдельно. `std::move`, `std::forward` и `std::exchange` объявлены в заголовке `<utility>`.

## 1. Зачем нужна семантика перемещения

**Семантика копирования** создаёт независимое значение на основе существующего. Для класса, владеющего динамическим буфером, глубокое копирование обычно требует выделить новую память и скопировать элементы.

**Семантика перемещения** позволяет создать или изменить объект, используя ресурсы другого объекта, значение которого больше не требуется сохранять. Например, вместо копирования большого массива можно передать владение уже выделенным буфером.

```cpp
#include <string>
#include <utility>

void example() {
    std::string source(1'000'000, 'x');

    std::string copy = source;             // Копирование.
    std::string destination = std::move(source); // Возможность перемещения.
}
```

После копирования `copy` содержит собственное значение, равное исходному. При перемещении `destination` получает значение, которое было в `source` до операции, а `source` остаётся существующим объектом, состояние которого определяется правилами его типа.

Для динамического буфера типичная разница в трудоёмкости такова:

$$
T_{\text{copy}}(n)=O(n), \qquad T_{\text{move}}(n)=O(1).
$$

**Это модель конкретного ресурса, а не универсальный закон.** Перемещение встроенного массива требует обработки его элементов. Короткая строка может храниться внутри самого объекта. Стоимость перемещающего присваивания также зависит от освобождения прежнего ресурса и, у контейнеров, от аллокаторов.

Перемещение не означает физического переноса объекта в памяти. Адрес исходного объекта сам по себе не меняется: меняются его поля и отношения владения ресурсами.

## 2. Категории значений выражений

### 2.1. Категория принадлежит выражению

У выражения есть **тип** и **категория значения**. Это разные характеристики.

В основных примерах используются три категории:

| Категория | Смысл | Примеры |
|---|---|---|
| `lvalue` | Выражение, обозначающее объект или функцию с идентичностью; не является `xvalue` | `x`, `s`, `*ptr` |
| `prvalue` | Выражение, вычисляющее значение или инициализирующее результирующий объект | `42`, `x + 1` для `int`, `std::string("abc")` |
| `xvalue` | Выражение, обозначающее объект, ресурсы которого разрешено использовать повторно | `std::move(s)` |

Объединяющие категории:

$$
\text{glvalue}=\text{lvalue}\cup\text{xvalue},
$$

$$
\text{rvalue}=\text{prvalue}\cup\text{xvalue}.
$$

Каждое выражение относится ровно к одной из трёх основных категорий. Например, `xvalue` одновременно относится к `glvalue` и `rvalue`.

**Rvalue — более широкое понятие, чем «временный объект».** Выражение `std::move(s)` является rvalue, хотя обозначает уже существующий именованный объект `s`.

### 2.2. Правило «слева или справа от равно» ненадёжно

Названия `lvalue` и `rvalue` исторические. Нельзя определять категорию только по положению относительно `=`:

```cpp
int x = 10;
int y = x;  // x стоит справа, но выражение x — lvalue.

const int z = 20;
// z = 30;  // Ошибка: z — lvalue, но изменять const-объект нельзя.
```

### 2.3. Тип ссылки не определяет категорию выражения с её именем

```cpp
int&& ref = 10;
int value = ref;
```

Переменная `ref` объявлена как rvalue-ссылка `int&&`, но **обычное выражение `ref` является lvalue**: оно именует объект.

Это относится и к параметрам функций:

```cpp
void consume(std::string&& text) {
    std::string a = text;            // Копирование: text — lvalue.
    std::string b = std::move(text); // Перемещение из того же объекта.
}
```

Специальные правила неявного перемещения в `return` рассмотрены отдельно. Они не отменяют это правило для обычного использования параметра в теле функции.

## 3. Lvalue-ссылки и rvalue-ссылки

### 3.1. Основные формы ссылок

```cpp
T&        // Lvalue-ссылка на изменяемый T.
const T&  // Lvalue-ссылка на const T.
T&&       // Rvalue-ссылка на T, если T — фиксированный тип.
```

Для одного типа `T`, без преобразований между разными типами:

| Ссылка | Изменяемый lvalue | Const lvalue | Неконстантный rvalue |
|---|---:|---:|---:|
| `T&` | Да | Нет | Нет |
| `const T&` | Да | Да | Да |
| `T&&` | Нет | Нет | Да |

`const T&` также связывается с константными rvalue. Обычная `T&&` не связывается с `const T`, поскольку это потребовало бы отбросить `const`.

### 3.2. Связывание ссылки не перемещает ресурс

```cpp
std::string text = "hello";
std::string&& ref = std::move(text);
```

Здесь не создаётся второй объект `std::string` и не вызывается его конструктор перемещения. `ref` ссылается на тот же объект, что и имя `text`.

Перемещение произойдёт при соответствующей операции:

```cpp
std::string another = std::move(ref);
```

Теперь создаётся новый объект `another`, а выражение справа позволяет выбрать перемещающий конструктор.

### 3.3. Как ссылки участвуют в перегрузке

```cpp
void inspect(const std::string& text); // Может принимать lvalue и rvalue.
void inspect(std::string&& text);      // Принимает неконстантный rvalue.

std::string s = "abc";
const std::string cs = "def";

inspect(s);                  // const std::string&
inspect(cs);                 // const std::string&
inspect(std::string("abc")); // std::string&&
inspect(std::move(s));       // std::string&&
inspect(std::move(cs));      // const std::string&
```

**Выбор перегрузки с `T&&` ещё не означает, что ресурс был передан.** Всё зависит от действий внутри выбранной функции.

## 4. Что делает std::move

### 4.1. Суть операции

**`std::move(expr)` — приведение, которое для объектных типов предоставляет выражение категории `xvalue`, сохраняя `const` и другие квалификаторы исходного объекта.**

Оно позволяет дальнейшей операции выбрать перегрузку для rvalue. Само `std::move` не выделяет память, не освобождает ресурс и не вызывает конструктор перемещения.

Упрощённая реализация, использующая синтаксис C++14:

```cpp
template<class T>
constexpr std::remove_reference_t<T>&& my_move(T&& value) noexcept {
    return static_cast<std::remove_reference_t<T>&&>(value);
}
```

Для этого фрагмента нужен также `<type_traits>`. В C++11 вместо `std::remove_reference_t<T>` используется `typename std::remove_reference<T>::type`.

Последовательность:

1. Определяется тип аргумента.
2. Из типа убирается ссылка.
3. К полученному типу добавляется `&&`.
4. Возвращается ссылка, связанная с исходным объектом.

### 4.2. Разбор по типам

Пусть объявлены `std::string s` и `const std::string cs`:

| Выражение | Тип результата, записанный через `decltype` | Категория |
|---|---|---|
| `s` | `decltype(s)` — `std::string`; `decltype((s))` — `std::string&` | `lvalue` |
| `std::move(s)` | `std::string&&` | `xvalue` |
| `std::move(cs)` | `const std::string&&` | `xvalue` |

У `decltype` для непомещённого в скобки имени переменной действует специальное правило: он возвращает объявленный тип. Для анализа категории используют `decltype((expression))`:

- `T&` соответствует `lvalue`;
- `T&&` соответствует `xvalue`;
- `T` соответствует `prvalue`.

Это правило относится к обычным выражениям, для которых не задействованы специальные случаи `decltype`.

### 4.3. Почему std::move может приводить к копированию

```cpp
const std::string source = "hello";
std::string target = std::move(source); // Копирование.
```

Обычный перемещающий конструктор строки принимает `std::string&&`. Он не может связаться с `const std::string&&`. Копирующий конструктор принимает `const std::string&`, поэтому остаётся подходящим.

Аналогично, если у класса нет подходящей операции перемещения, но есть доступное копирование из `const T&`, rvalue может быть скопирован.

Однако **отсутствующая и явно удалённая операция — разные случаи**:

```cpp
struct Item {
    Item() = default;
    Item(const Item&) = default;
    Item(Item&&) = delete;
};

Item first;
// Item second = std::move(first); // Ошибка: выбрана удалённая Item(Item&&).
```

Разрешение перегрузки не обязано «отступать» к копированию после выбора удалённой функции. Для defaulted move-конструктора, определённого как удалённый, существует отдельное правило исключения из разрешения перегрузки; его нельзя переносить на явно написанное `= delete`.

### 4.4. Когда использовать std::move

Применяй `std::move`, когда **осознанно разрешаешь следующей операции изменить значение исходного объекта ради передачи ресурсов**:

```cpp
std::vector<std::string> words;
std::string word = "example";

words.push_back(std::move(word));
// Далее не полагаемся на прежнее содержимое word.
```

Для встроенного `int`:

```cpp
int a = 42;
int b = std::move(a);
```

`b` получает число `42`; `a` также остаётся равным `42`. Отдельного ресурса, который можно передать, здесь нет.

## 5. Конструктор и оператор перемещения

### 5.1. Две разные операции

```cpp
class Resource {
public:
    Resource() = default;
    Resource(const Resource& other);            // Копирующий конструктор.
    Resource(Resource&& other) noexcept;        // Перемещающий конструктор.

    Resource& operator=(const Resource& other); // Копирующее присваивание.
    Resource& operator=(Resource&& other) noexcept; // Перемещающее присваивание.
};
```

**Конструктор** инициализирует новый объект. **Присваивание** меняет уже существующий объект и должно учесть ресурс, которым тот владел до операции.

```cpp
Resource a;
Resource b = std::move(a); // Конструирование b.

Resource c;
c = std::move(b);         // Присваивание уже существующему c.
```

Сам знак `=` в объявлении `Resource b = ...` не означает вызов оператора присваивания.

### 5.2. Полный пример класса с единоличным владением буфером

Класс ниже показывает передачу указателя, освобождение старого ресурса при присваивании и согласованное состояние источника.

```cpp
#include <algorithm>
#include <cstddef>
#include <utility>

class Buffer {
private:
    std::size_t size_ = 0;
    int* data_ = nullptr;

public:
    explicit Buffer(std::size_t size = 0)
        : size_(size),
          data_(size == 0 ? nullptr : new int[size]{}) {}

    ~Buffer() {
        delete[] data_;
    }

    Buffer(const Buffer& other)
        : Buffer(other.size_) {
        if (size_ != 0) {
            std::copy_n(other.data_, size_, data_);
        }
    }

    Buffer& operator=(const Buffer& other) {
        if (this != &other) {
            Buffer temporary(other);
            swap(temporary);
        }
        return *this;
    }

    Buffer(Buffer&& other) noexcept
        : size_(std::exchange(other.size_, 0)),
          data_(std::exchange(other.data_, nullptr)) {}

    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            size_ = std::exchange(other.size_, 0);
            data_ = std::exchange(other.data_, nullptr);
        }
        return *this;
    }

    void swap(Buffer& other) noexcept {
        std::swap(size_, other.size_);
        std::swap(data_, other.data_);
    }

    std::size_t size() const noexcept {
        return size_;
    }

    int& operator[](std::size_t index) {
        return data_[index];
    }

    const int& operator[](std::size_t index) const {
        return data_[index];
    }
};

int main() {
    Buffer a(3);
    a[0] = 7;

    Buffer b = a;            // Независимая копия.
    Buffer c = std::move(a); // Передача буфера от a к c.
    b = std::move(c);        // Старый буфер b освобождается.
}
```

Предусловие `operator[]`: `index < size()`. Проверка границ в этом учебном классе не выполняется.

### 5.3. Разбор перемещающего конструктора

Выражение `std::exchange(other.data_, nullptr)`:

1. Сохраняет прежнее значение указателя `other.data_`.
2. Записывает в `other.data_` значение `nullptr`.
3. Возвращает прежний указатель для инициализации `data_` нового объекта.

Аналогично размер передаётся новому объекту, а в исходном становится нулём.

**Инвариант класса:** при нулевом размере указатель равен `nullptr`; при положительном размере объект единолично владеет буфером соответствующей длины. После перемещения этот инвариант соблюдается у обоих объектов.

Если просто скопировать владеющий указатель и оставить его в источнике, деструкторы двух объектов попытаются освободить одну и ту же память. Это приводит к неопределённому поведению.

### 5.4. Почему в перемещении полей снова нужен std::move

```cpp
class Record {
    std::string name_;

public:
    Record(Record&& other) noexcept
        : name_(std::move(other.name_)) {}
};
```

Хотя параметр имеет тип `Record&&`, выражение `other` — lvalue. Поэтому `other.name_` тоже lvalue. Без `std::move` поле `name_` копировалось бы.

Для сырого указателя `std::move(pointer)` не передаёт владение и не обнуляет источник: указатель является скалярным значением. В `Buffer` состояние источника меняется благодаря `std::exchange`, а не благодаря особенностям указателя.

## 6. Состояние объекта после перемещения

### 6.1. Объект продолжает существовать

Перемещение не вызывает деструктор источника и не завершает его время жизни.

Для типов стандартной библиотеки действует общее правило: **после перемещения объект находится в корректном, но неопределённом по содержимому состоянии, если для конкретного типа или операции не установлена более сильная гарантия**.

Это означает, что инварианты сохраняются, но прежнее значение считать сохранённым нельзя.

```cpp
std::string a = "hello";
std::string b = std::move(a);

bool empty = a.empty(); // Допустимо проверить фактическое состояние.
a = "new value";      // Допустимо присвоить новое значение.
```

Нельзя универсально утверждать, что перемещённая строка пуста. Нельзя вызывать операцию с невыполненным предусловием:

```cpp
if (!a.empty()) {
    char first = a.front(); // Условие для front() проверено.
}
```

Для пользовательских классов состояние после перемещения задаётся их реализацией и контрактом. У `Buffer` оно явно определено: `size() == 0`.

### 6.2. Сильная гарантия конкретного типа: unique_ptr

```cpp
#include <memory>
#include <utility>

auto first = std::make_unique<int>(42);
auto second = std::move(first);

// first == nullptr, second владеет числом 42.
```

`std::unique_ptr` нельзя копировать: копирование нарушило бы единоличное владение. Его перемещение передаёт владение, оставляя исходный указатель пустым.

### 6.3. Повторное перемещение

Повторно переместить корректный объект стандартной библиотеки обычно допустимо, но первая операция уже могла забрать прежний ресурс:

```cpp
auto p = std::make_unique<int>(10);
auto q = std::move(p);
auto r = std::move(p);

// q владеет числом, p и r пусты.
```

Поэтому допустимость второй операции не означает, что она передаст то же значение.

## 7. Автоматические специальные функции и noexcept

### 7.1. Правило нуля

**Правило нуля:** если ресурсами владеют подходящие стандартные типы, чаще всего не нужно самостоятельно определять деструктор, копирование и перемещение.

```cpp
struct Document {
    std::string title;
    std::vector<int> data;
};
```

Компилятор формирует операции через соответствующие операции полей. Это обычно проще и надёжнее ручной работы с памятью.

### 7.2. Правило пяти

Если класс самостоятельно управляет ресурсом и требует специального деструктора или операций копирования/перемещения, нужно совместно продумать пять функций:

1. Деструктор.
2. Копирующий конструктор.
3. Копирующее присваивание.
4. Перемещающий конструктор.
5. Перемещающее присваивание.

**Продумать не значит обязательно реализовать все пять вручную.** Некоторые можно задать как `= default` или запретить через `= delete`.

Неявные перемещающие операции объявляются только при выполнении специальных условий. В частности, пользовательское объявление деструктора, копирующего конструктора или копирующего присваивания подавляет автоматическое объявление перемещающих операций. Даже деструктор `~T() = default;` считается пользовательски объявленным.

При явном объявлении перемещающей операции неявные копирующие операции могут определяться как удалённые. Поэтому нельзя добавлять одну специальную функцию, не проверив остальные.

**Defaulted перемещение работает по полям.** Сырой указатель будет скопирован как адрес; источник автоматически не обнулится. Поэтому для класса с единоличным владением сырым указателем `= default` обычно не реализует нужный контракт.

### 7.3. Зачем noexcept

`noexcept` сообщает, что исключение не выйдет из функции:

```cpp
Buffer(Buffer&& other) noexcept;
Buffer& operator=(Buffer&& other) noexcept;
```

Если исключение всё же покинет такую функцию, будет вызван `std::terminate`. Поэтому указывать `noexcept` можно только при соответствующих гарантиях всех выполняемых действий.

При перераспределении памяти `std::vector` должен создавать элементы в новом буфере. Если перемещение может бросить исключение, а копирование доступно, реализация часто выбирает копирование, чтобы сохранить сильную гарантию исключений.

`std::move_if_noexcept(x)` позволяет выразить такой выбор:

- возвращает `const T&`, если перемещающее конструирование потенциально бросает исключение, а копирование доступно;
- иначе возвращает `T&&`.

Если копирование запрещено, потенциально бросающее перемещение всё равно может понадобиться; гарантии конкретной операции контейнера следует рассматривать отдельно.

У автоматически сформированных перемещающих операций спецификация исключений зависит от операций базовых классов и полей.

## 8. Forwarding references и сворачивание ссылок

### 8.1. Почему T&& не всегда означает обычную rvalue-ссылку

```cpp
template<class T>
void relay(T&& value);
```

Если `T` **выводится из аргумента вызова** и параметр записан как `T&&` без добавленного `const`, такой параметр является **forwarding reference**, то есть пересылающей ссылкой. Также встречается название «универсальная ссылка».

Он может принимать и lvalue, и rvalue, сохраняя информацию о категории при выводе `T`.

```cpp
int x = 10;
const int cx = 20;

relay(x);            // T = int&,       параметр int&.
relay(cx);           // T = const int&, параметр const int&.
relay(10);           // T = int,        параметр int&&.
relay(std::move(x)); // T = int,        параметр int&&.
```

### 8.2. Правила сворачивания ссылок

В шаблонах и псевдонимах типов подстановка может привести к комбинации ссылок. Она сворачивается:

| Комбинация | Результат |
|---|---|
| `T& &` | `T&` |
| `T& &&` | `T&` |
| `T&& &` | `T&` |
| `T&& &&` | `T&&` |

**Если хотя бы одна из двух ссылок — `&`, результатом будет `&`. Только две `&&` дают `&&`.**

При `relay(x)` выводится `T = int&`. Тогда тип параметра получается из `T&&`, то есть из сочетания `int& &&`, и сворачивается в `int&`.

Синтаксис таблицы — схема подстановки типов. Нельзя непосредственно объявить переменную как `int& && x`.

### 8.3. Где forwarding reference отсутствует

```cpp
void f(std::string&& value); // Фиксированный тип: обычная rvalue-ссылка.

template<class T>
void g(const T&& value);     // Не forwarding reference: добавлен const.

template<class T>
void h(std::vector<T>&& value); // Не форма T&&: lvalue-вектор не принимается.

template<class T>
struct Box {
    void put(T&& value);     // T уже определён типом Box<T>.

    template<class U>
    void relay(U&& value);   // U выводится при вызове: forwarding reference.
};
```

Для `Box<int>` параметр `put` имеет тип `int&&`. Особые правила forwarding-вывода здесь не действуют. Если сам `T` является ссылочным типом, итоговый тип определяется обычным сворачиванием ссылок.

Явное задание типа также может убрать нужный вывод:

```cpp
int x = 1;
// relay<int>(x); // Ошибка: параметр int&& не связывается с lvalue x.
relay(x);        // T выводится как int&.
```

### 8.4. auto&&

При обычном выводе из выражения `auto&&` ведёт себя как forwarding reference:

```cpp
int x = 10;
const int cx = 20;

auto&& a = x;   // int&
auto&& b = cx;  // const int&
auto&& c = 10;  // int&&
```

Но выражения `a`, `b`, `c` с этими именами — lvalue.

Исключение из общего шаблона — вывод из списка в фигурных скобках:

```cpp
auto&& values = {1, 2, 3}; // std::initializer_list<int>&&.
```

Такую инициализацию нельзя объяснять обычным forwarding-выводом из одного выражения.

## 9. Что делает std::forward

### 9.1. Назначение

**`std::forward<T>(value)` восстанавливает категорию аргумента в соответствии с типом `T`, сохранённым при выводе шаблонного параметра.**

Для правильного forwarding-применения:

- если исходный аргумент был lvalue, результат остаётся lvalue;
- если исходный аргумент был rvalue, результат становится xvalue.

Квалификатор `const` также сохраняется. Исходный `prvalue` при передаче через именованный параметр не восстанавливается именно как `prvalue`: он передаётся дальше как `xvalue`, то есть как rvalue.

### 9.2. Почему нельзя просто передать имя параметра

```cpp
void process(const std::string& text);
void process(std::string&& text);

template<class T>
void bad_relay(T&& value) {
    process(value); // value — lvalue при любом исходном аргументе.
}

template<class T>
void good_relay(T&& value) {
    process(std::forward<T>(value));
}
```

Вызов `bad_relay(std::string("abc"))` теряет возможность выбрать `process(std::string&&)`. Правильная обёртка сохраняет её.

### 9.3. Пошаговый разбор

Для `good_relay(s)`, где `s` — изменяемая строка-lvalue:

1. Выводится `T = std::string&`.
2. Тип параметра `T&&` сворачивается в `std::string&`.
3. Выражение `value` является lvalue.
4. `std::forward<T>(value)` возвращает `T&&`.
5. После сворачивания это `std::string&`, поэтому вызывается lvalue-перегрузка.

Для `good_relay(std::string("abc"))`:

1. Выводится `T = std::string`.
2. Параметр имеет тип `std::string&&`.
3. Выражение `value` по-прежнему является lvalue.
4. `std::forward<T>(value)` возвращает `std::string&&`.
5. Результат — xvalue; выбирается rvalue-перегрузка.

В основе механизма лежит приведение вида `static_cast<T&&>(value)`. У стандартного `std::forward` есть две перегрузки и ограничения, поэтому такое приведение объясняет идею, но не заменяет полное объявление стандартной функции.

### 9.4. Почему нельзя заменить forward на move

```cpp
template<class T>
void wrong_relay(T&& value) {
    process(std::move(value));
}
```

При вызове `wrong_relay(s)` эта обёртка передаст пользовательский lvalue как rvalue. Если `process` заберёт ресурс, значение `s` изменится, хотя вызывающий код не выражал такого намерения.

| Свойство | `std::move(x)` | `std::forward<T>(x)` |
|---|---|---|
| Основное назначение | Разрешить потребление конкретного объекта | Сохранить категорию исходного аргумента |
| Результат для объектных типов | Всегда xvalue | Lvalue или xvalue в зависимости от `T` |
| Типичный контекст | Последнее использование объекта, параметр фиксированного `T&&` | Шаблонный параметр forwarding reference |
| Выполняет само перемещение | Нет | Нет |

`std::forward` не определяет первоначальную категорию автоматически по имени `x`: она закодирована в явно переданном шаблонном аргументе `T`.

## 10. Идеальная передача аргументов

### 10.1. Фабрика объектов

**Perfect forwarding**, или идеальная передача, позволяет обёртке передавать аргументы дальше с сохранением их ссылочных и cv-свойств, значимых для выбора перегрузки.

```cpp
#include <memory>
#include <string>
#include <utility>

struct Person {
    std::string name;

    explicit Person(const std::string& value)
        : name(value) {}

    explicit Person(std::string&& value)
        : name(std::move(value)) {}
};

template<class T, class... Args>
std::unique_ptr<T> make_object(Args&&... args) {
    return std::make_unique<T>(std::forward<Args>(args)...);
}

int main() {
    std::string name = "Alice";

    auto first = make_object<Person>(name);            // Копирует name.
    auto second = make_object<Person>(std::move(name)); // Перемещает из name.
    auto third = make_object<Person>(std::string("Bob")); // Принимает временный объект.
}
```

`Args&&...` — пакет forwarding references. Выражение `std::forward<Args>(args)...` применяет передачу **отдельно к каждому** аргументу с его собственным выведенным типом.

### 10.2. Обёртка над произвольным вызываемым объектом

```cpp
#include <functional>
#include <utility>

template<class F, class... Args>
decltype(auto) invoke_forward(F&& function, Args&&... args) {
    return std::invoke(
        std::forward<F>(function),
        std::forward<Args>(args)...
    );
}
```

`std::invoke` доступен с C++17 и поддерживает обычные функции, функциональные объекты и указатели на члены.

`decltype(auto)` сохраняет ссылочный тип результата. Обычный возвращаемый `auto` вывел бы значение, отбросив ссылку. При этом сохранение ссылки не продлевает время жизни объекта: возвращаемая ссылка должна оставаться действительной.

Передавать нужно и `function`: у вызываемого объекта могут быть разные `operator() &` и `operator() &&`.

### 10.3. Границы идеальной передачи

Не всякая синтаксическая форма является выражением, из которого можно вывести `T`:

```cpp
template<class T>
void accept(T&& value);

// accept({1, 2, 3}); // Ошибка: из такого списка не выводится T.
```

Можно явно создать объект:

```cpp
accept(std::vector<int>{1, 2, 3});
```

Другие ограничения: перегруженное имя функции без уточнения нужной перегрузки и битовые поля, к которым нельзя привязать обычную изменяемую ссылку. Perfect forwarding не отменяет общих правил языка.

### 10.4. Не передавай один потребляемый аргумент дважды

```cpp
template<class T>
void duplicate_use(T&& value) {
    consume(std::forward<T>(value));
    consume(std::forward<T>(value));
}
```

Если первая `consume` переместила ресурс, вторая получает уже изменённый объект. Категория сохранилась, но прежнее содержимое — нет.

Проектируй обёртку так, чтобы потребляющая передача каждого аргумента была однократной, либо явно задавай смысл повторного использования.

## 11. Выбор способа передачи параметров

### 11.1. Выбор должен отражать контракт функции

| Задача | Типичный параметр | Действия внутри |
|---|---|---|
| Прочитать дорогой для копирования объект | `const T&` | Читать без владения |
| Изменить объект вызывающего кода | `T&` | Изменять переданный объект |
| Получить собственное значение | `T value` | При необходимости переместить локальный параметр в поле |
| Явно принять объект для потребления | `T&&` с фиксированным `T` | Использовать `std::move(value)` в потребляющей операции |
| Передать аргумент в шаблонной обёртке | `T&&` с выводом `T` | Использовать `std::forward<T>(value)` |

Для небольших дешёвых типов, например `int`, передача по значению обычно естественна.

### 11.2. Приём по значению и перемещение в поле

```cpp
class User {
    std::string name_;

public:
    explicit User(std::string name)
        : name_(std::move(name)) {}
};
```

Если передать lvalue-строку, параметр `name` создаётся копированием, затем поле — перемещением из параметра. При передаче rvalue параметр может быть создан перемещением или напрямую, после чего перемещается в поле.

Здесь `std::move` оправдан: `name` — собственный локальный параметр, его прежнее значение после инициализации поля не требуется.

Этот подход уменьшает число перегрузок, но не всегда минимизирует число операций. Для часто вызываемых функций выбор между передачей по значению и парой `const T&` / `T&&` зависит от использования и стоимости типа.

### 11.3. Параметр T&& сам по себе не гарантирует потребление

```cpp
void store(std::unique_ptr<int>&& pointer) {
    auto saved = std::move(pointer);
}
```

При вызове `store(std::move(p))` связывание параметра не перемещает `p`. Владение передаётся в строке инициализации `saved`.

Если функция должна безусловно получить собственный `unique_ptr`, часто проще выразить это передачей по значению:

```cpp
void store(std::unique_ptr<int> pointer) {
    // Функция уже владеет ресурсом через собственный параметр.
}
```

### 11.4. push_back и emplace_back

```cpp
std::vector<std::string> names;
std::string name = "Alice";

names.push_back(name);             // Копирование нового элемента.
names.push_back(std::move(name));  // Перемещение нового элемента.
names.emplace_back(5, 'x');        // Строка "xxxxx" строится из аргументов.
```

`emplace_back` передаёт аргументы конструктору элемента. Он не гарантирует, что копирований вообще не будет:

```cpp
std::string other = "Bob";
names.emplace_back(other);            // Копирование из lvalue.
names.emplace_back(std::move(other)); // Перемещение из rvalue.
```

При росте ёмкости контейнеру дополнительно может понадобиться перенести уже существующие элементы.

## 12. Возврат объектов и устранение копирования

### 12.1. Возвращай локальный объект по значению

```cpp
std::vector<int> make_numbers() {
    std::vector<int> result{1, 2, 3};
    return result;
}
```

Компилятор может применить **NRVO** — named return value optimization — и построить `result` непосредственно в месте результата вызова. Отдельного копирования или перемещения тогда нет.

Если NRVO не применяется, для такого локального неконстантного объекта действуют правила неявного перемещения. Для `std::vector<int>` будет доступен перемещающий конструктор.

```cpp
std::vector<int> make_numbers_bad() {
    std::vector<int> result{1, 2, 3};
    return std::move(result); // Лишает этот return возможности NRVO.
}
```

Поэтому для обычного возврата локального объекта того же типа **пиши `return result;`**.

### 12.2. Прямое построение из prvalue с C++17

```cpp
std::string make_text() {
    return std::string("hello");
}

std::string text = make_text();
```

В соответствующих случаях prvalue того же типа непосредственно инициализирует результирующий объект: промежуточный объект для последующего перемещения не требуется. Это гарантированное правило C++17, а NRVO для именованного локального объекта остаётся необязательным.

### 12.3. Версионная оговорка

Правила неявного перемещения в `return` уточнялись между версиями стандарта. В C++23 подходящие для перемещения выражения в таком контексте рассматриваются как xvalue. Для обычного возврата локального `std::string` или `std::vector` практическая рекомендация сохраняется: возвращай имя без лишнего `std::move`.

Эту рекомендацию нельзя механически переносить на любой объект. Например, возврат по значению из lvalue-ссылочного параметра не даёт общего разрешения забрать ресурс вызывающего кода:

```cpp
std::string copy_text(const std::string& text) {
    return text; // Копирование.
}
```

## 13. Время жизни и висячие ссылки

### 13.1. Rvalue-ссылка не является владельцем

Наличие `&&` не гарантирует, что объект будет жить достаточно долго. Время жизни определяется правилами создания и уничтожения объектов, а не фактом возможности перемещения.

```cpp
std::string&& bad() {
    std::string local = "hello";
    return std::move(local); // Возвращается ссылка на уничтожаемый local.
}
```

После выхода из функции `local` уничтожается. Возвращённая ссылка становится висячей, и использование объекта через неё приводит к неопределённому поведению.

Правильный вариант — вернуть значение:

```cpp
std::string good() {
    std::string local = "hello";
    return local;
}
```

### 13.2. Прямое связывание с временным объектом

```cpp
const std::string& first = std::string("abc");
std::string&& second = std::string("def");
```

В этих локальных объявлениях время жизни соответствующего временного объекта продлевается до времени жизни ссылки.

Но продление не передаётся произвольно через вызовы функций:

```cpp
auto&& broken = std::move(std::string("abc"));
// После точки с запятой временная строка уже уничтожена.
```

`std::move` возвращает ссылку на временный аргумент; новая ссылка не продлевает его время жизни через этот вызов. После завершения полного выражения `broken` — висячая ссылка.

Безопасные варианты для хранения:

```cpp
auto value = std::string("abc");   // Собственный объект.
auto&& reference = std::string("abc"); // Прямое продление времени жизни.
```

**`std::move` и `std::forward` не являются средствами продления времени жизни.** При передаче временного объекта в функцию он обычно живёт до конца полного выражения с вызовом, но сохранённая на будущее ссылка может стать висячей.

## 14. Типичные ошибки и алгоритм проверки

### 14.1. Ошибки и исправления

| Ошибка | Причина | Правильный подход |
|---|---|---|
| Считать, что `std::move(x)` уже передал ресурс | Это только приведение | Найти следующую операцию, которая действительно потребляет объект |
| Передавать именованный `T&&` без приведения | Имя параметра — lvalue | `std::move` для потребляющего параметра; `std::forward<T>` для пересылающего |
| Использовать `std::move` внутри любой шаблонной обёртки | Может забрать ресурс из исходного lvalue | Сохранять категорию через `std::forward<T>` |
| Ждать обычного перемещения из `const` | `const` сохраняется | Не делать потребляемый объект константным без необходимости |
| Читать прежнее значение после перемещения | Содержимое могло измениться | Учитывать контракт типа, присвоить новое значение или проверить состояние |
| Писать `return std::move(local)` автоматически | Препятствует NRVO | Для обычного локального результата писать `return local` |
| Возвращать ссылку на локальную переменную | Объект уничтожается при выходе | Возвращать объект по значению |
| Применить `= default` к владельцу сырого указателя | Указатель копируется, владение не разделяется корректно | Использовать RAII-поле или явно реализовать передачу владения |
| Обещать `noexcept` при бросающих действиях | Исключение приведёт к `std::terminate` | Проверить гарантии вызываемых операций |
| Дважды пересылать потребляемый rvalue | После первого вызова состояние могло измениться | Выполнить потребляющую передачу один раз |

### 14.2. Как разобрать строку кода

Для выражения вроде `target = std::move(source)` последовательно ответь:

1. **Что объявлено?** Каковы типы `target` и `source`, есть ли `const`?
2. **Какова категория исходного выражения?** Имя `source` обычно lvalue.
3. **Что меняет приведение?** `std::move(source)` даёт xvalue, сохраняя `const`.
4. **Какая операция выполняется?** В этом примере — присваивание существующему объекту.
5. **Какие перегрузки доступны?** Есть ли подходящая перемещающая операция, не удалена ли она?
6. **Что реально делает выбранная функция?** Передаёт владение, копирует поля или выполняет другой алгоритм?
7. **Что гарантировано после операции?** Можно ли дальше использовать источник и какие операции допустимы?
8. **Достаточно ли времени жизни?** Не остаётся ли ссылка на уже уничтоженный объект?

Не делай вывод о фактическом перемещении только по наличию `&&` или `std::move` в записи.

## 15. Задачи для самопроверки

### 15.1. Какая перегрузка вызывается?

```cpp
void check(const std::string&);
void check(std::string&&);

std::string s = "abc";
const std::string cs = "def";
std::string&& ref = std::move(s);

check(s);             // 1
check(std::move(s));  // 2
check(cs);            // 3
check(std::move(cs)); // 4
check(ref);           // 5
check(std::move(ref));// 6
```

**Ответ:**

| Вызов | Параметр выбранной перегрузки | Объяснение |
|---|---|---|
| 1 | `const std::string&` | `s` — lvalue |
| 2 | `std::string&&` | Результат `std::move(s)` — неконстантный xvalue |
| 3 | `const std::string&` | `cs` — const lvalue |
| 4 | `const std::string&` | `const std::string&&` не связывается с изменяемой `std::string&&` |
| 5 | `const std::string&` | Имя `ref` — lvalue |
| 6 | `std::string&&` | Приведение снова даёт неконстантный xvalue |

Эти ответы описывают выбор перегрузки. Из её объявления нельзя узнать, перемещает ли она ресурс внутри.

### 15.2. Что выводится для T?

```cpp
template<class T>
void inspect(T&& value);

int x = 1;
const int cx = 2;

inspect(x);
inspect(cx);
inspect(3);
inspect(std::move(cx));
```

**Ответ:**

| Аргумент | `T` | Тип параметра после сворачивания | `std::forward<T>(value)` |
|---|---|---|---|
| `x` | `int&` | `int&` | Lvalue |
| `cx` | `const int&` | `const int&` | Const lvalue |
| `3` | `int` | `int&&` | Xvalue |
| `std::move(cx)` | `const int` | `const int&&` | Const xvalue |

### 15.3. Что произойдёт с unique_ptr?

```cpp
auto p = std::make_unique<int>(7);
auto&& alias = std::move(p);
auto q = std::move(alias);
```

**Разбор:**

1. `p` владеет числом `7`.
2. `alias` связывается с объектом `p`. Владение пока не передано.
3. При создании `q` вызывается перемещающий конструктор `unique_ptr`.
4. `q` владеет числом; `p` пуст. `alias` продолжает ссылаться на тот же теперь пустой `p`.

### 15.4. Исправь обёртку

```cpp
template<class T>
void relay(T&& value) {
    process(std::move(value));
}
```

**Исправление:**

```cpp
template<class T>
void relay(T&& value) {
    process(std::forward<T>(value));
}
```

В исходной версии даже lvalue передавался дальше как rvalue. Исправленная версия сохраняет намерение вызывающего кода.

### 15.5. Проверка понимания через decltype

```cpp
#include <string>
#include <type_traits>
#include <utility>

int main() {
    std::string s = "abc";
    const std::string cs = "def";
    std::string&& ref = std::move(s);

    static_assert(std::is_same_v<decltype(s), std::string>);
    static_assert(std::is_same_v<decltype((s)), std::string&>);
    static_assert(std::is_same_v<decltype(ref), std::string&&>);
    static_assert(std::is_same_v<decltype((ref)), std::string&>);
    static_assert(std::is_same_v<decltype(std::move(s)), std::string&&>);
    static_assert(std::is_same_v<decltype(std::move(cs)), const std::string&&>);
}
```

`decltype(ref)` показывает объявленный тип переменной, а `decltype((ref))` — ссылочный тип, соответствующий категории выражения. Это позволяет отделить rvalue-ссылку как тип от lvalue как категории её имени.

## Главное

1. **Перемещение позволяет повторно использовать ресурсы объекта.** Реальная передача происходит в выбранном конструкторе, присваивании или другой потребляющей функции.
2. **`std::move` — приведение, а не операция передачи ресурса.** Оно создаёт возможность выбрать rvalue-перегрузку, сохраняя `const`.
3. **Имя rvalue-ссылки обычно является lvalue-выражением.** Поэтому внутри перемещающей операции поля источника часто нужно явно передавать через `std::move`.
4. **Forwarding reference требует подходящей формы и вывода типа.** `T&&` с выводимым `T` принимает обе категории благодаря специальному выводу и сворачиванию ссылок.
5. **`std::forward<T>` сохраняет категорию исходного аргумента.** Используй его в пересылающей обёртке вместо безусловного `std::move`.
6. **Перемещённый объект продолжает существовать.** Его дальнейшее использование определяется контрактом типа; прежнее содержимое не гарантируется.
7. **Для обычных классов предпочитай правило нуля.** При ручном владении ресурсом совместно продумывай все специальные функции и корректное состояние источника.
8. **`noexcept` влияет на стратегии стандартных контейнеров.** Указывай его, когда операция действительно гарантированно не выпускает исключения.
9. **Обычный локальный результат возвращай без `std::move`.** Это сохраняет возможность NRVO и позволяет неявное перемещение в предусмотренных случаях.
10. **Перемещение и пересылка не обеспечивают время жизни.** Ссылки на локальные или уже уничтоженные временные объекты остаются опасными независимо от наличия `&&`.
